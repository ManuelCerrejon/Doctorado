01 · PROBLEMA Y OBJETIVO

De reconstruir audio a comprenderlo

Modelos como Audio-MAE aprenden representaciones tratando de reconstruir regiones ocultas del espectrograma.

Sin embargo, reconstruir correctamente características tiempo-frecuencia puede obligar al modelo a dedicar capacidad a detalles acústicos de bajo nivel que no son necesariamente relevantes para comprender el significado del sonido.

BEATs propone sustituir la reconstrucción por una tarea de predicción de etiquetas acústicas discretas con contenido semántico.

IDEA PRINCIPAL

Semantic-rich acoustic tokens

El modelo no intenta reconstruir exactamente la región acústica que ha sido ocultada.

En su lugar, intenta identificar qué token acústico discreto representa esa región.

El objetivo es que dichos tokens capturen progresivamente información de mayor nivel semántico y descarten detalles acústicos redundantes.

02 · METODOLOGÍA GENERAL

Entrenamiento iterativo

01

Tokenizar el audio

Un tokenizador acústico convierte los patches del audio en una secuencia de etiquetas discretas.

02

Entrenar BEATs

Parte de la entrada se oculta y el Transformer intenta predecir los tokens acústicos correspondientes.

03

BEATs se convierte en teacher

Una vez entrenado, el propio modelo proporciona representaciones utilizadas para mejorar el tokenizador.

04

Refinar el tokenizador

Mediante knowledge distillation, el nuevo tokenizador aprende representaciones acústicas con mayor contenido semántico.

05

Nueva iteración

Las nuevas etiquetas discretas se utilizan como objetivos para entrenar otra versión de BEATs.

03 · ITERACIONES

Tokenizador y modelo se refinan mutuamente

ITERACIÓN 1

Random Projection

Cold start

Como todavía no existe un modelo BEATs entrenado, las primeras etiquetas se obtienen mediante un tokenizador inicializado aleatoriamente.

→
ITERACIÓN 2

Self-Distilled

BEATs iter1 como teacher

El tokenizador aprende utilizando conocimiento extraído del modelo entrenado en la primera iteración.

→
ITERACIÓN 3

Refinamiento

BEATs iter2 como teacher

El proceso se repite para generar etiquetas acústicas progresivamente más relacionadas con la semántica.

BEATS ITER3+

Una variante importante

BEATs iter3+ utiliza como teacher un BEATs iter2 que previamente ha sido fine-tuned mediante información supervisada.

Por tanto, esta variante no utiliza exclusivamente información auto-supervisada: conocimiento procedente de las etiquetas downstream entra también en el proceso de generación del nuevo tokenizador.

04 · ACOUSTIC TOKENIZER

Primera iteración

INPUT

Patch

Región de la representación acústica.

→
PROJECTION

Random Linear

Una proyección lineal aleatoria transforma el patch.

→
CODEBOOK

Nearest Neighbor

Se busca el embedding más cercano dentro del codebook.

→
OUTPUT

Discrete Token

El índice del embedding elegido se utiliza como etiqueta.

05 · SELF-DISTILLED TOKENIZER

Aprender tokens más semánticos

12-layer Transformer

El encoder del tokenizador transforma los patches acústicos.

→

Codebook

Las representaciones se cuantizan mediante embeddings aprendibles.

→

3-layer estimator

Intenta reproducir las representaciones generadas por el modelo teacher.

Knowledge distillation

El objetivo del tokenizador incluye similitud coseno con las representaciones producidas por el teacher.

Esto permite que las etiquetas discretas incorporen progresivamente información aprendida por el modelo BEATs.

06 · PREPROCESADO

Representación acústica

01

Resampling

La forma de onda se convierte a 16 kHz.

02

Mel Filterbank

Se extraen características Mel de 128 dimensiones.

03

Ventanas

Se utilizan ventanas Povey de 25 ms y desplazamiento de 10 ms.

04

Normalización

Las características se normalizan a media 0 y desviación estándar 0,5.

05

Patches

La representación se divide en patches de 16 × 16.

07 · MODELO

Audio Transformer

BEATS

90 M parámetros

  • Backbone ViT

POSICIÓN

Relative Position

  • Convolutional positional embedding
  • Gated relative position bias
  • DeepNorm para estabilidad

08 · PREENTRENAMIENTO

Masked Audio Modeling

01

Tokenizar

El tokenizador genera la etiqueta discreta correspondiente a cada patch.

02

Mask 75 %

Se oculta aleatoriamente el 75 % de los patches de entrada.

03

Encoder

El ViT procesa únicamente los patches no enmascarados.

04

Label Predictor

Las representaciones visibles se utilizan para predecir las etiquetas acústicas ocultas.

05

Cross Entropy

La pérdida se calcula únicamente sobre las posiciones enmascaradas.

LIMITACIONES

Aspectos a tener en cuenta

Dependencia del tokenizador

La calidad del objetivo de preentrenamiento depende directamente de la calidad de las etiquetas generadas por el tokenizador.

Proceso iterativo

El refinamiento requiere entrenar repetidamente modelos y tokenizadores.

Iter3+ usa supervisión

El mejor modelo incorpora conocimiento procedente del fine-tuning supervisado dentro del proceso de preentrenamiento.

RELACIÓN CON LA TESIS

¿Qué aporta a mi investigación?

BEATs es especialmente interesante porque muestra cómo transformar una señal acústica continua en unidades discretas con mayor contenido semántico.

Estas unidades pueden proporcionar una interfaz compacta entre modelos perceptivos y sistemas posteriores de comprensión o razonamiento.

Además, el refinamiento iterativo entre tokenizador y modelo plantea una conexión natural con aprendizaje continuo y adaptación: las unidades utilizadas para representar el audio podrían modificarse a medida que cambia el dominio acústico.

Al mismo tiempo, esta posibilidad obliga a estudiar cómo controlar la estabilidad del aprendizaje y evitar que una adaptación incorrecta deteriore las representaciones previamente aprendidas.
